Розділ 01

Системи контролю версій та Git

Основна теорія, яка допоможе зрозуміти, навіщо взагалі потрібен Git і як він працює

📁

Що таке СКВ?

Система контролю версій (VCS — Version Control System) — це програмний інструмент, що відстежує та керує змінами у файлах з часом. Вона дозволяє повернутися до будь-якої попередньої версії, порівнювати зміни та відновлювати файли після помилок.

🌐

Типи СКВ

Локальні — зберігають версії лише на комп'ютері (RCS).
Централізовані — один центральний сервер (SVN, CVS).
Розподілені — кожен клієнт має повну копію репозиторію (Git, Mercurial).

🔶

Що таке Git?

Git — безкоштовна розподілена СКВ із відкритим кодом, створена Лінусом Торвальдсом у 2005 році для розробки ядра Linux. Сьогодні це найпопулярніша у світі система контролю версій.

⚙️

Як працює Git?

Git зберігає дані як знімки (snapshots) файлової системи, а не різниці між версіями. Кожен commit — це знімок усіх файлів у певний момент. Це забезпечує надзвичайно швидку роботу.

🔀

Гілки та злиття

Головна сила Git — гілки (branches). Вони дозволяють розробляти нові функції ізольовано, не впливаючи на основний код. Злиття (merge) та перебазування (rebase) — ключові операції командної роботи.

☁️

Хостинг та Git

Популярні платформи для роботи з Git-репозиторіями: GitHub, GitLab, Bitbucket. Вони додають веб-інтерфейс, pull requests, code review та інші інструменти для командної розробки.

Розділ 02

Можливості та переваги Git

Чому саме Git став стандартом індустрії для мільйонів розробників і компаній

1

Розподілена архітектура

Кожен розробник має повну копію репозиторію. Робота можлива без інтернету, а ризик втрати даних мінімальний.

2

Швидкість і продуктивність

Більшість операцій виконуються локально, без мережевих запитів — Git надзвичайно швидкий.

3

Ефективне гілкування

Створення гілок займає мілісекунди. Це заохочує ізольовану розробку нових функцій і безпечне експериментування.

4

Цілісність даних

Кожен об'єкт має SHA-1 хеш. Неможливо змінити дані непоміченим — Git гарантує цілісність усієї історії.

5

Відкритий вихідний код

Git повністю безкоштовний і відкритий. Величезна спільнота, розширена документація та підтримка на всіх платформах.

6

Гнучкі робочі процеси

Git підтримує різні workflow: Git Flow, GitHub Flow, Trunk-Based Development — вибирайте під свій проєкт.

7

Повна історія змін

Зберігається повна хронологія всіх змін з автором, датою та коментарем. Легко знайти, коли і ким введено помилку.

8

Командна співпраця

Pull requests та code review дозволяють командам ефективно рецензувати код перед об'єднанням у основну гілку.

Розділ 03

10 базових команд Git

Найважливіші команди, які потрібно знати кожному розробнику для початку роботи з Git

1

git init — ініціалізація репозиторію

bash
$ git init # Ініціалізує новий Git-репозиторій у поточній директорії # Створює приховану папку .git з усіма службовими файлами $ git init my-project # Створює нову папку my-project та ініціалізує в ній репозиторій
Перша команда при старті нового проєкту. git init створює порожній Git-репозиторій або reinitializes existing one. Після виконання в поточній директорії з'явиться прихована папка .git.
2

git clone — клонування репозиторію

bash
$ git clone https://github.com/user/repo.git # Клонує репозиторій у нову папку з назвою repo $ git clone https://github.com/user/repo.git my-folder # Клонує в папку з вказаною назвою
Копіює існуючий репозиторій разом з усією повною історією змін. Автоматично налаштовує remote «origin» на вихідний URL.
3

git status — стан робочої директорії

bash
$ git status # Показує поточний стан: змінені, нові та staged файли $ git status -s # Короткий формат виводу (M = modified, A = added, ? = untracked)
Найбільш часто використовувана команда. Показує: на якій гілці ви знаходитесь, які файли змінені, які готові до commit (staged), а які ще не відстежуються.
4

git add — додавання змін до staging

bash
$ git add index.html # Додає конкретний файл до staging area $ git add . # Додає всі змінені файли в поточній директорії $ git add -p # Інтерактивний режим — вибір конкретних частин файлу
Переміщає зміни до staging area (індексу) — проміжної зони перед commit. Дозволяє точно контролювати, які зміни потраплять у наступний commit.
5

git commit — збереження змін

bash
$ git commit -m "feat: add navigation menu" # Зберігає staged зміни з повідомленням $ git commit --amend # Виправляє останній commit (повідомлення або зміст)
Записує знімок staged змін у локальний репозиторій. Кожен commit — це точка відновлення. Пишіть зрозумілі повідомлення в стилі Conventional Commits.
6

git branch — управління гілками

bash
$ git branch # Показує список локальних гілок (* = поточна) $ git branch feature/login # Створює нову гілку feature/login $ git branch -d feature/login # Видаляє гілку після злиття
Гілки в Git — надлегкі покажчики на конкретні commits. Вони дозволяють ізолювати розробку нових функцій від стабільного коду в main.
7

git switch — перемикання між гілками

bash
$ git switch main # Перемикається на гілку main $ git switch -c feature/new-page # Створює нову гілку і одразу перемикається на неї $ git checkout main # Застаріла, але ще активно вживана альтернатива
git switch — сучасна команда (Git 2.23+) для перемикання між гілками. Замінює частину функцій git checkout, роблячи призначення команд більш явним.
8

git merge — злиття гілок

bash
$ git switch main # Спочатку перейдіть на цільову гілку $ git merge feature/login # Зливає гілку feature/login у поточну (main) $ git merge --no-ff feature/login # Злиття зі створенням merge commit (зберігає історію гілки)
Об'єднує зміни з іншої гілки в поточну. При конфліктах злиття Git позначає проблемні місця — розробник вирішує їх вручну, потім робить commit.
9

git pull / git push — синхронізація з remote

bash
$ git pull origin main # Отримує та зливає зміни з remote репозиторію $ git push origin main # Відправляє локальні commits на remote сервер $ git push -u origin feature/login # Відправляє нову гілку та встановлює upstream tracking
git pull = git fetch + git merge. Завантажує зміни з remote та об'єднує з локальними. git push — навпаки, відправляє ваші локальні commits на сервер.
10

git log — перегляд історії

bash
$ git log # Повна історія commits (з хешами, авторами, датами) $ git log --oneline --graph --all # Компактна графічна візуалізація всіх гілок $ git log --author="Ivan" --since="2025-01-01" # Фільтр за автором та датою
Відображає хронологію commits у репозиторії. Флаг --oneline --graph перетворює лог на наочне дерево гілок — незамінний інструмент для розуміння структури проєкту.
